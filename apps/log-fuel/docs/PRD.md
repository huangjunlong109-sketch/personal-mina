## 2. 背景与目标

- **背景**：替代第三方「油耗查询」工具，数据与功能自主可控；支持从原工具导出的 Excel 迁移入库。
- **目标**：多车辆独立管理；首页看板 + 双 Tab 图表；记一笔与历史列表；云开发持久化；**不做**换机同步、公告、底栏外链、同车型对比、累计节省。

---

## 3. 已定决策（需求基线）

| 序号 | 议题 | 决策 |
| :---: | :--- | :--- |
| 1 | 存储与同步 | **微信云开发**；**不需要**换机同步 |
| 2 | 车辆 | **多辆车**；每辆车**独立数据**（记录、统计、图表仅看当前车） |
| 3 | 同车型油耗 | **不做** |
| 4 | 累计节省 | **不做**（KPI 五格：去掉「累计节省」） |
| 5 | 满枪默认值（导入无列时） | 默认 **已跳枪**；**仅当支付总额(元)为整数**时记为 **未跳枪**；有小数则 **已跳枪** |
| 6 | Excel 与计算不一致 | **以 Excel 字段为准**；发现逻辑异常时对记录打 **「有问题」** 标记，待用户检查 |
| 7 | 重复导入同一 `记录 ID` | **更新**已有记录 |
| 8 | 底栏三项（FAQ / 优惠加油 / 反馈） | **不做** |
| 9 | 顶部公告条 | **不做** |
| 10 | 油号 | **92# / 95# / 98# / 0#** 固定枚举即可 |
| 11 | 导航结构 | **需要 Tab**：除首页外，包含 **我的 / 设置** 等（与多车、导入、云能力配套） |

## 4. 用户与信息架构

### 4.1 角色

- 单一微信用户；可绑定多辆车，切换「当前车辆」后全局数据视图切换。

### 4.2 Tab 建议（可微调命名）

| Tab | 承载内容 |
| :--- | :--- |
| 油耗 | 原「油耗查询」首页：KPI + 图表 + 入口「历史记录」「记油耗」 |
| 我的 | 当前车辆卡片、**我的车库**（选车 / 添加车辆）、导入 Excel、退出登录（若用登录）等 |
| 设置 | 云环境无关项：如关于、清除缓存（若有）、数据说明；**导入也可放「我的」** 二选一集中即可 |

> 实现时可将「油耗」为默认 Tab；「我的」内嵌车库底部弹层与参考图一致。

### 4.3 页面清单

- Tab：油耗首页、我的、设置（或合并「我的+设置」为两个 Tab，第三 Tab 占位需产品再定——PRD 按用户要求「需要 Tab」保留三 Tab，第三格可用「我的」拆出「车辆」子页避免空洞）。
- **油耗查询（首页）**：无公告、无累计节省、无同车型文案；KPI **5 项**：最新油耗、平均油耗、日均里程、累计加油(L)、累计油费(元)。
- **记油耗**：表单 + 保存；满枪用户可手改；导入衍生规则见 §6。
- **历史油耗**：时间轴列表；支持编辑、删除；展示「有问题」角标/筛选。
- **我的车库**：底部弹层或全屏列表；当前车勾选；添加新车（品牌/车型/车牌等字段开发时定最小集）。
- **导入**：选 xlsx → 解析 → 绑定**当前车辆** → 写云数据库；结果汇总。

## 5. Excel 导入规范

### 5.1 明细列（与导出一致）

表头（第一行）：`记录 ID`、`加油日期`、`油号`、`加油量 (L)`、`支付单价 (元)`、`支付总额 (元)`、`行驶里程 (km)`、`增加里程 (km)`、`最新油耗 (L/100km)`、`每公里油费 (元)`。

- 读取 **第一个工作表**；遇 **「统计汇总」** 行或连续空行则停止明细。
- **记录 ID**：作为幂等键；再次导入 **update** 同 ID 记录（归属当前导入所选车辆，若 ID 跨车冲突策略：以**最后一次导入所选车辆**覆盖或禁止跨车——建议 **记录 ID 仅在同一车辆内唯一**，跨车重复 ID 提示错误）。

### 5.2 导入写入字段

除 Excel 列外，写入：

- `vehicleId`（当前车）
- `tankFull`：按 §3 表第 5 条规则由 **支付总额是否整数** 推导
- `importSource`：`excel`
- `dataOk` / `issueFlags`：见 §6

## 6. 数据校验与「有问题」标记

**原则**：展示与统计以 **Excel 数值** 为主（最新油耗、每公里油费、增加里程等**不强制改写成重算值**）。

**建议标记为「有问题」**（可同时打多个 flag，UI 展示「待检查」）：

1. **金额联动**：`|支付总额 - 加油量×支付单价|` 超过约定容差（如 0.06 元或 1 分位四舍五入后仍不等）。
2. **里程联动**：`|当前行驶里程 - 上一条行驶里程 - 增加里程|` 与链式上一条比较容差外不一致（需按日期+里程或记录 ID 排序后链式计算）。
3. **油耗粗验**：`|最新油耗 - 加油量/增加里程*100|` 超容差（增加里程≤0 时跳过此项并标记「间隔异常」）。
4. **必填缺失**：日期/油量/单价/总额/里程任一无效。

用户可在详情页 **确认无误** 清除标记或保留备注；编辑后可选重新跑校验。

---

## 7. 核心计算（首页汇总）

- **最新油耗**：当前车辆按加油日期倒序第一条有效记录的「最新油耗」字段（Excel 一致）。
- **平均油耗**：与行业常见一致即可——建议 **总加油量 / 总增加里程 × 100**（总增加里程为 Excel 增加里程之和，若有「有问题」记录是否计入——建议 **仍计入但首页给提示条「含 n 条待核实记录」**）。
- **日均里程**：建议 **总增加里程 / 统计天数跨度(天)** 或 **有记录的自然日数**——开发前在实现注释中写死一种并与你对齐验收。
- **累计加油 / 累计油费**：当前车所有记录 `加油量`、`支付总额` 求和。

图表：

- **油耗 Tab**：折线 = 每条记录的「最新油耗」或日期序列；虚线 = 平均油耗（与 KPI 一致算法）。
- **油费 Tab**：按月汇总 `支付总额`；虚线 = 月均油费。

## 8. 云开发数据模型（草案）

**集合 `vehicles`**：`_openid`、名称、品牌、车型、车牌、创建时间等。

**集合 `fuel_records`**：

- Excel 对应字段 + `vehicleId`、`tankFull`、`issueFlags`（数组或位图）、`issueNote`、`confirmedByUser`（bool）、`importSource`、`createTime`、`modifyTime`
- 软删字段按你项目统一规范（若阿里规范则 `is_deleted` 等——以仓库统一为准）

安全：仅创建者可读写本人 `vehicleId` 下数据（云函数或 DB 权限规则校验）。

---

## 9. 非功能

- 不做换机同步：即 **不做跨用户合并**，单账号云库即可。
- 小程序包体：xlsx 解析可考虑云函数解析上传文件，或客户端轻量库——排期时二选一。

## 10. 开发计划（建议迭代）

### Phase 0 — 工程与云（0.5～1d）

- 初始化/清理 demo 页与组件；`app.json` Tab 三页骨架；云开发 `env` 配置；建库与权限规则草案。

### Phase 1 — 车辆与空态（1～1.5d）

- 车辆 CRUD；「我的车库」弹层；当前车 `global`/`storage`；空数据引导。

### Phase 2 — 加油记录写读（1.5～2d）

- 记油耗页 + 校验 + 写云；历史列表 + 月分组 + 编辑删除；单条详情与「有问题」展示。

### Phase 3 — 首页 KPI + 图表（2～3d）

- 五格 KPI；`ec-canvas` / F2 等选型接折线与柱状；切换当前车刷新。

### Phase 4 — Excel 导入（2～3d）

- 选文件、解析、批量 upsert（记录 ID）、满枪推导、异常标记、结果页（成功/更新/失败行）。

### Phase 5 — 联调与打磨（1～2d）

- 边界：首条无间隔、同日多条、小数精度；性能小批量测试；文案与样式对齐参考稿（无公告/无底栏/无节省/无同车型）。

**合计粗估**：约 **9～13 人天**（单人顺序开发量级，可并行压缩）。

## 11. 验收要点（抽检）

- [ ] 三 Tab 可切换；当前车切换后首页/历史/图表数据一致。
